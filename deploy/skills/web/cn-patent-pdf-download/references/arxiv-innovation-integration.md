# 无对比文件案件的创造性增强：arXiv 论文提炼整合（2026-09-04 实测）

## 触发场景
案件 01_source 为空、评审人批注未给具体对比文件号（如视频摘要案件 〔项目代号〕），创造性论证停在"相对公知常识"层面。

## 用户明确指示（2026-09-04，不可违背）
**不要使用 NPL 引用**。将论文中的创新点提炼出来作为本案创新点的一部分整合进整个方案中，简化已有常规手段，突出创新点。

## 正确做法：提炼整合（而非引用）
1. arXiv 检索相关论文（export.arxiv.org/api/query，按案涉技术方向 3-5 篇）
2. 从论文提炼**可借鉴机制思路**，转化为本案自身技术手段，写成"本方案通过…实现"（无"据论文"痕迹）：
   - 偏好分解类论文 → 偏好子空间随会话演化更新（式）
   - 因果叙事类论文 → 跨模态因果事件检测 + 因果强度度量 + 因果闭包完整度评分
   - 权衡类论文 → 用户价值分 / 内容风险分量化仲裁
3. **简化常规手段**：偏好提取/渲染等常规流程压缩为概述，注明"非本案创新点"
4. **突出创新点**：六/关键点重构为聚焦的创新主题（如"多偏好冲突解决 + 因果串联合成"）
5. 检索材料（论文摘要+关联分析）归档 01_source 作参考，**不写入交底书**

## 为什么（用户视角）
NPL 引用是双刃剑——reviewer 需验证论文真实性与"反噬风险"（论文是否公开了本案创新点）；提炼整合进方案反而更自足、无被认定为现有技术的风险，且让方案本身更充实。

## 实测案例（视频摘要案件 V4→V5）
- V4：3 篇 arXiv NPL 引用（NarrativeBridge 2406.06499 / Preference Decomposition 2203.16942 / Harm Mitigation 2406.09882），reviewer PASS 但用户要求重构
- V5：移除全部 NPL，把三篇思路提炼为式4~式8（子空间演化/因果强度/价值分/风险分/因果完整度），第五部分 56.2%，双复核 PASS
